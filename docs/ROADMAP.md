# Roadmap

This file is the plan of sqlite. The Status page of the site reads it, and the tracker of the project mirrors it.

| ID | Item | Status | Summary |
| --- | --- | --- | --- |
| SQ-1 | The first package | done | Version 0.1.0: the pragmas, the migrations by `user_version`, `BEGIN IMMEDIATE` transactions, the event log and the filter of the warning. |
| SQ-2 | A schema version for each part of a file | done | A library and the app keep their tables in one file, and each part has its own version. |
| SQ-3 | The event log as a grow-only set | done | A duplicate changes nothing, a conflict is reported, and the log has reads after a position and by type. |
| SQ-4 | The fault kind of each error | done | The kind of each error of `node:sqlite` and the action that it needs, from the result code. |
| SQ-5 | Release 0.2.0 | done | Release SQ-2, SQ-3 and SQ-4, and give the API to the first user. |
| SQ-6 | Recovery of a broken file | done | Version 0.2.1: an integrity check, the quarantine of a file with its WAL and SHM files, the salvage of a log and an online backup. |
| SQ-7 | Nested transactions | done | Version 0.2.2: savepoints in a transaction, so a work can call a different work that writes. The event log can join a transaction of the caller. |
| SQ-8 | The file of an older app | done | Version 0.2.3: adopt a file that has tables but no schema version. |
| SQ-9 | The first move | done | An app with its own event log moves to this package. Its store opens its log with `openEventLog`, and its earlier files open with their events. |
| SQ-10 | The second move | done | An app with four stores moves to this package. Each of its four stores opens, migrates and writes through this package. One store reads with `readTransaction`. |
| SQ-11 | The third move | done | An app with its own store and migrations moves to this package. Its store opens, migrates and writes through this package, with one baseline step by `user_version`. |
| SQ-12 | The map of homes | done | The map of homes tells that the package is on npm. |
| SQ-13 | The site | done | The home page has a live demo of the event log: three copies in SQLite in WebAssembly exchange notes, and the page shows the conflicts and checks the join laws after each change. A probe uses the demo in CI at each width. |
| SQ-14 | Standard Schema validators | done | Version 0.3.1: the `parse` of a log is a function or a validator of the Standard Schema, for example a schema of zod 4. A refused value gives a `SchemaError`. |
| SQ-15 | Projections | done | Version 0.2.4: a file of a projection or a cache opens empty when its version differs, as the index and the vectors of polite-crawler do today. SQ-10 needs it. |
| SQ-16 | Newer files kept | done | Version 0.2.5: with `newer: "keep"`, an older app does no step on a newer file and keeps its version. SQ-10 needs it. |
| SQ-17 | The portable entry | done | Version 0.2.6: the entry `@mark1russell7/sqlite/portable` operates on each connection with the type `SqlConnection`, also in a browser. SQ-13 needs it. |
| SQ-18 | The adapter of SQLite in WebAssembly | done | Version 0.3.0: `wasmConnection` gives a `SqlConnection` over `@sqlite.org/sqlite-wasm`, with no dependency. The types of the entry `/portable` do not name `node:sqlite`. SQ-13 uses it. |
| SQ-19 | Read transactions | done | Version 0.3.2: `readTransaction` reads one snapshot and does not take the write lock. The second move uses it for its vectors. |
| SQ-20 | The move of codeatlas | done | codeatlas opens its catalog through this package: the open, the read-only open, the transactions, the added columns, the clear of the cache and the checkpoint. Version 0.3.3 adds the parts that it lacks. |
| SQ-21 | The move of the client procedures | done | The SQLite procedures of the client monorepo use this package: the connection of each engine, the transactions, the dry run and the columns. Version 0.3.3 adds the adapter of sql.js, the read-only open and the dry run. Version 0.3.4 keeps each statement of sql.js usable after a save. |
| SQ-22 | The gate of `node:sqlite` | done | The conventions check refuses a value import of `node:sqlite` out of this package. An exception has a reason. The rule `home-module` is in conventions 0.41.15. |
| SQ-23 | The oldest Node.js of the users | done | Version 0.3.4: the package operates on Node.js 22.13, the first Node.js with `node:sqlite` and no flag. CI runs the tests on Node.js 22.13. |
| SQ-24 | The remaining moves | done | A query of codeatlas finds public code that opens `node:sqlite` or `better-sqlite3` directly, or has its own migrations, WAL pragmas or busy retries. Each hit gets a decision: move, keep with a reason, or not SQLite. Each move is one PR in the repository of its owner. [The rows](MOVES.md) also show a lost write of `sql.js` next to a WAL file. The page has [the state of each move](MOVES.md#the-state-of-each-move). Done on 2026-11-16: `@procedures/sqlite` 0.61.0 and `@procedures/ios-backup` 0.60.1 open their files through this package. |
| SQ-25 | A crash and fault suite | done | Seeded fault plans stop the writer process in a transaction, a migration step, a checkpoint and a salvage. Each committed transaction stays after a reopen, and `integrity_check` passes. The suite operates in CI only, on Node.js 22.13, 24 and 26. It found a fault of `iterate()` on Node.js 22.13, and version 0.3.8 corrects the salvage. |
| SQ-26 | The scale ladder | in progress | Targets for each power of ten: 10^3 to 10^7 events in one log, and files of 1 MB to 10 GB. CI measures the append rate, the reads, the open, the migrations and the recovery time. The power-cut test in `packages/sqlite/power` holds the data loss of each `synchronous` setting: the disk tier of `@mark1russell7/harness` loses each write after the last fsync on LazyFS, and the job `power` of `crash.yml` examines each claim of `openDatabase`. The bench is in `packages/sqlite/scale`, and the ruleset of `main` asks for `Scale OK`. Each job measures all rungs on one runner, and the gate holds the growth of each measure on 6 runners. A flat measure grows at most 2 times for 10 times the events, and a linear measure at most 20 times. |
| SQ-27 | The checked open of a log | done | Version 0.3.7: `openCheckedEventLog` checks the file of a log before the open. A broken file goes into quarantine, and a new file gets each readable event. A test stops the recovery at each step, and the next open completes it. Version 0.3.8 corrects the salvage on Node.js 22.13. |
| SQ-28 | The synced transaction | in progress | Version 0.3.10: `syncedTransaction` gives the sync of `FULL` to one commit on a connection with `NORMAL`. Thus an app keeps the low cost of `NORMAL` for most writes, and the disk keeps the writes that must stay. Two cases of the power-cut test hold the claim: the disk keeps each commit up to the last synced transaction. The first user is a broker of memory leases. |
| SQ-29 | The snapshot of a fold | in progress | Version 0.4.1: `openFoldSnapshot` keeps the folded state of an app at one position of its log. The next start folds only the events after that position. A read gives no snapshot for a different version or key, or when the log does not have the event of the mark at its position. The first user is the start of an alert system. |
